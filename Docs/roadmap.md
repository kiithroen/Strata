# 로드맵

## 지금 상태

Vite + TypeScript + Three.js 웹 앱 틀과 위젯 갤러리가 있다. 노트 카드와 시간축 위젯이 구현돼 있다([widgets.md](widgets.md)).

- 확인한 것: 단위 테스트(주사율 무관성, 펼친 카드 화면 맞춤, 달력 눈금, 묶음, 배치), 데스크톱 브라우저 캡처(시간축 연·월·일·노트 단계, 묶음 탭으로 들어가기, 낱장 펼치기·닫기, ◀ 이동, 세로·가로에 가까운 화면비)
- 확인하지 않은 것: 폰 실기기에서의 탭 반응·120Hz 움직임·폴더블 접기와 펼치기, 카드 텍스처 메모리(떠 있는 카드 텍스처 장수 × 크기)

## 다음 작업

차례대로 한다. 각 위젯은 갤러리 데모, 단위 테스트, 화면 캡처 확인까지 마쳐야 끝난다.

1. **카메라·제스처 위젯**: 한 손가락 끌기(시간 이동, 관성), 핀치(로그 축척, 손가락 아래 시점 고정, 놓으면 `nearestLevel`로 스냅). 지금 `input/tap.ts`의 탭 판정과 함께 하나의 제스처 해석기로 묶는다. 제스처 해석은 포인터 이벤트 열을 넣으면 결과가 나오는 순수 로직으로 두어 테스트한다. 끄는 동안에는 `AxisController.current`를 바로 움직이고, 놓을 때만 목표로 붙인다. 시간축 데모의 임시 단추는 이때 뺀다.
   - 손가락 아래 시점 고정: 핀치 중심의 화면 높이로 레일 위 깊이를 구하고(`axis.railY`와 시야각), 그 깊이의 시각이 축척이 바뀐 뒤에도 같은 깊이에 오도록 `focusTime`을 옮긴다.
2. **실기기 확인**: 폰에서 갤러리를 열어([development.md](development.md) "폰에서 열기") 제스처 손맛, 카드 글자 가독성, 고리 배치 밀도, 안개 거리를 보고 `src/config.ts`에서 고친다. 카드 텍스처 메모리가 부담이면 떠 있는 카드 텍스처를 아틀라스로 묶거나 거리별로 해상도를 낮춘다.
3. **후처리 위젯**: 화면 전체 디더링, 주사선, 색수차, 잡음. 효과마다 켜고 끈다. 카드 셰이더의 주사선·잡음과 겹치지 않게 정리한다.
4. **노트 보기**: 펼친 카드에서 사진 전체 보기로 넘어가는 전환.

그 뒤에 실제 데이터로 넘어간다: 사진 가져오기(EXIF 날짜), 저장(OPFS 또는 IndexedDB와 저장소 영구화), 캡션 입력(2D 화면). 실제 사진은 디코딩이 비동기라 `PhotoSource.render`를 비동기로 바꾸고, 사진이 오기 전에는 테두리와 라벨만 그린 카드를 보인다.
