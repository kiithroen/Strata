# 로드맵

## 지금 상태

Vite + TypeScript + Three.js 웹 앱 틀과 위젯 갤러리가 있다. 주 화면은 우주 보기(`cosmos`)다. 시간 묶음은 가장 최근 시점을 원점에 두고 3차원 사방으로 감겨 퍼지는 고정 로그 구면 나선 위의 빛나는 노드이고, 노드에서 노트 점이 방사형 선으로 뻗으며 한 단계 위 허브에 가지로 이어진다. 화면은 짙은 남색 바탕에 청록·파랑 빛 테마다. 노트 몇 장은 노드 둘레를 돌풍에 날리는 양면 홀로그램 카드(사진은 청록 창, 메모는 글 양에 맞춘 포스트잇 색 쪽지, 문서는 파일 탭 창)로 날아다니고, 멀수록 단순한 모양이 된다. 은하에서 노드나 카드를 처음 탭하면 그 노드로 다가가 빛이 커지고, 한 번 더 탭하면 그 묶음이 날짜별 수평 층으로 쌓인 지층 보기로 바뀌고(카드는 지층에서만 펼친다), 뒤로 가면 은하로 돌아온다. 멀어지면 묶음 위에 태그 워드 클라우드가 뜨고 카드가 사라진다. 은하의 날짜 글자는 화면에 같은 크기로 보인다. 카메라는 표준 3D 궤도 시점(회전·팬·연속 줌·노드 포커스)이며, 시간 모델은 시간축 위젯이, 종이는 노트 카드 위젯이, 포인터 입력·3D 궤도·시간 띠는 카메라·제스처 위젯이 맡는다([widgets.md](widgets.md)).

- 확인한 것: 단위 테스트(주사율 무관성, 프레임 통계·품질 프리셋과 저장 값, 달력 눈금·묶음, 로그 구면 나선·궤도 거리, 허브·노트 점 배치, 종이 비행·돌풍·뒹굴기, 묶음이 바뀔 때의 이동, 지층 층 쌓기·창 깔기·눕힌 자세, 태그 세기·워드 클라우드 배치·보이는 정도, 포인터 제스처 해석, 은하 탭 두 단계, 3D 궤도 회전·팬·연속 줌·포커스 이동, 시간축 끌기·관성·핀치 시점 고정·단계 스냅)
- 실기기 확인 도구: 오른쪽 위 설정 화면의 성능 표시와 품질(프리셋·항목별), 큐브맵에 굽는 성운
- 실기기 성능: 폰 한 대에서 기본 품질(가짜 노트 수)로 주사율만큼 프레임이 나온다. 조작하는 동안 120Hz, 손을 떼면 60Hz인데 기기의 적응형 주사율로 보인다
- 확인하지 않은 것: 폰 실기기에서의 탭·끌기·핀치 손맛과 반응, 홀로그램 카드·지층 보기·워드 클라우드의 실기기 모습, 폴더블 접기와 펼치기, 다른 기기의 성능, 실데이터 수백 장에서의 카드 텍스처 메모리

## 다음 작업

차례대로 한다. 각 위젯은 갤러리 데모, 단위 테스트, 화면 캡처 확인까지 마쳐야 끝난다.

1. **실기기 손맛과 두 단계 탐색 다듬기**: 폰에서 갤러리를 열어([development.md](development.md) "폰에서 열기", "설정 화면") 보고 `src/config.ts`에서 고친다. 웹 페이지는 주사율을 요청할 수 없으니 손을 뗐을 때의 60Hz는 앱으로 감쌀 때 안드로이드 쪽에서 요청해 본다.
   - 은하 탭 두 단계: 다가가는 거리(`cosmos.approach.planetDistance`, `hubDistance`)와 다가간 노드 표시(`cosmos.approach.glowScale`)가 손가락으로 충분히 알아볼 만한지
   - 제스처 손맛, 종이 크기·속도와 탭 정확도(돌풍이 셀 때 너무 빠른지), 선 굵기, 은하 밀도
   - 카드: 단순한 모양·흑백으로 바뀌는 시점(`card.lod`), 빛 번짐(`card.holo.glowRatio`), 메모 크기 범위(`card.memo`)
   - 지층 보기: 층 간격·내려다보는 각도·창 크기(`strata.layerGap`, `strata.pitch`, `strata.cardScale`), 배치를 더 흩을지(`strata.cellGap`, `strata.yawJitter`). 아래층으로 가려면 판 빈 곳을 정확히 탭해야 하므로 위아래로 끌어 층을 넘기는 조작을 검토한다
   - 워드 클라우드: 멀리서 본 은하의 낱말 밀도(`cloud.maxWords`, `cloud.show`)와, 멀리서 층들이 화면에서 붙을 때 층마다 뜬 낱말이 겹치는 문제(층 낱말을 옆으로 비키거나 바라보는 층만 크게 보이는 등)
2. **실데이터 테스트 · 2D 카드 모드 · 노트 보기**: 로컬 사진(파일·폴더 선택, EXIF 날짜)과 구글 킵 수준의 짧은 메모·태그를 임시 주입해 실제 수백 장 규모에서 비동기 디코딩(`PhotoSource.render` 비동기화)과 텍스처 풀링을 검증한다. 설정 화면의 성능 표시로 텍스처 수와 프레임을 보고, 텍스처 메모리가 문제면 카드 텍스처를 아틀라스로 묶거나 거리별로 해상도를 낮춘다. 동시에 `cosmos` 시점·선택 노드와 연동되는 **2D 카드 모드**(가독성·검색·메모/태그 입력 오버레이), 펼친 카드의 사진 전체 보기를 붙인다. 메모 입력에서 포스트잇 색을 고르면 노트의 `tint`(색 번호)로 저장한다.
3. **시각 확장 (성능 예산 내)**: 1~2단계에서 확인한 실기기 프레임 여유를 보고 **여러 해를 은하로** 묶는 바깥 단계와 **후처리 위젯**(블룸, 디더링, 색수차 — 효과별 토글, 카드 셰이더 주사선·잡음과 정리)을 반영한다.

그 뒤에 실제 저장소·동기화와 축 확장을 붙인다.

### 폰 앱과 동기화

- **앱**: 지금 웹 코드를 Capacitor로 감싼 안드로이드 앱으로 만들고 APK를 직접 설치한다. GitHub Pages 배포본은 가짜 데이터로 화면을 확인하는 미리보기로 남긴다.
- **로컬 저장**: 메타데이터(노트 번호, 시각, 캡션, 태그, 수정 시각)는 SQLite, 사진과 썸네일은 앱 파일 저장소에 둔다. 화면은 이것만 읽는다. 브라우저 저장소(IndexedDB·OPFS)는 지워질 수 있어 쓰지 않는다.
- **동기화**: 구글 드라이브의 보이는 폴더(`Strata/`) 하나에 노트마다 메타데이터 JSON 하나와 사진 파일 하나를 둔다. 권한은 앱이 만든 파일만 다루는 `drive.file` 범위로 한다. 앱을 열 때와 노트를 고친 뒤 드라이브 변경 목록(Changes API)으로 받고 보낸다. 같은 노트가 양쪽에서 바뀌면 수정 시각이 늦은 쪽이 이기고, 지운 노트는 지움 표시를 남긴다.
- **사진 크기**: 드라이브에는 줄인 사본(긴 변 기준)을 올리고 원본은 폰 갤러리에 둔다. 처음 동기화가 클 수 있어 와이파이에서만 사진을 받는 설정을 둔다.
- **준비**: 구글 클라우드 프로젝트와 안드로이드용 OAuth 클라이언트(패키지 이름, 서명 키 SHA-1)가 필요하다. 개인용은 앱을 테스트 상태로 두고 본인 계정을 테스트 사용자로 넣는다.

### 다른 축(태그)

태그가 입력되면 날짜 대신 태그를 축으로 고를 수 있게 한다. 지금 우주 보기는 날짜에 묶여 있어서(`AxisController`의 시각·축척, 달력 단위 묶음, 시각 → 깊이) 그때 아래처럼 나눈다.

- **묶음 공급자와 관련도**: 노트 목록을 받아 노드(키, 글자, 구성원, 각 구성원의 관련도, 위 노드, 정렬값)를 내는 인터페이스를 두고, 날짜 묶음을 그 구현 하나로 옮긴다. 태그 묶음이 두 번째 구현이다. 날짜 축의 시간 중심성 대신 태그 축에서는 태그 집중도(한 노드에 몰린 노트일수록 강한 인력)가 관련도가 된다.
- **정렬값 → 깊이**: 날짜는 시각을 그대로 쓴다. 태그는 순서가 없으니 정렬값(가장 최근 노트 시각, 노트 수 등)을 정해 나선 위 깊이로 바꾼다.
- **여러 소속**: 날짜는 노트 하나가 노드 하나에 속하지만 태그는 여러 노드에 속한다. 종이는 소속 노드들 사이(가중 평균 자리) 둘레를 날고, 소속 노드마다 실을 고리에 맨다. 실 여러 가닥이 한 종이로 모이는 모양이 된다.
- **단계(확대·축소)**: 날짜는 달력 단위로 합치고 가른다. 태그는 태그 계층(상위 태그)이나 묶음 크기로 합치고 가른다.
