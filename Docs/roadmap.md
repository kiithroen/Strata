# 로드맵

## 지금 상태

Vite + TypeScript + Three.js 웹 앱 틀과 위젯 갤러리가 있다. 주 화면은 우주 보기(`cosmos`)다. 시간 묶음은 나선팔 위의 행성, 노트는 그 둘레를 도는 위성 카드다. 시간 모델은 시간축 위젯이, 사진 카드는 노트 카드 위젯이 맡는다([widgets.md](widgets.md)).

- 확인한 것: 단위 테스트(주사율 무관성, 달력 눈금·묶음, 나선·고리·공전, 묶음이 바뀔 때의 이동), 데스크톱 브라우저 캡처(우주 보기 연·월·일·노트 단계, 행성 탭으로 들어가기, 위성 탭으로 펼치기·닫기, 세로·가로에 가까운 화면비)
- 확인하지 않은 것: 폰 실기기에서의 탭 반응·120Hz 움직임·폴더블 접기와 펼치기, 실기기 성능(먼지·성운의 화면 채움 비용, 카드 텍스처 메모리)

## 다음 작업

차례대로 한다. 각 위젯은 갤러리 데모, 단위 테스트, 화면 캡처 확인까지 마쳐야 끝난다.

1. **카메라·제스처 위젯**(우주 보기에 붙인다): 한 손가락 끌기(시간 이동, 관성), 핀치(로그 축척, 손가락 아래 시점 고정, 놓으면 `nearestLevel`로 스냅). 지금 `input/tap.ts`의 탭 판정과 함께 하나의 제스처 해석기로 묶는다. 제스처 해석은 포인터 이벤트 열을 넣으면 결과가 나오는 순수 로직으로 두어 테스트한다. 끄는 동안에는 `AxisController.current`를 바로 움직이고, 놓을 때만 목표로 붙인다. 임시 단추(`axisHud.ts`)는 이때 뺀다.
   - 손가락 아래 시점 고정: 핀치 중심에서 가장 가까운 행성(없으면 초점면)의 시각이 축척이 바뀐 뒤에도 같은 깊이에 오도록 `focusTime`을 옮긴다.
   - 손가락이 닿아 있는 동안 공전이 멈추는 지금 동작을 끌기·핀치에도 그대로 둔다.
2. **실기기 확인**: 폰에서 갤러리를 열어([development.md](development.md) "폰에서 열기") 제스처 손맛, 위성 카드 크기와 탭 정확도, 은하 밀도, 프레임 속도를 보고 `src/config.ts`에서 고친다. 무거우면 먼지 수·성운 해상도를 줄이고, 카드 텍스처는 아틀라스로 묶거나 거리별로 해상도를 낮춘다.
3. **여러 해를 은하로**: 연 단계보다 더 축소하면 해마다 은하 하나로 모이고, 은하를 탭하면 그 해로 들어간다. 지금 나선팔 모델을 은하 하나의 안쪽으로 두고 바깥 단계를 하나 더 얹는다.
4. **후처리 위젯**: 화면 전체 블룸(행성 빛 무리와 별), 디더링, 색수차. 효과마다 켜고 끈다. 카드 셰이더의 주사선·잡음과 겹치지 않게 정리한다.
5. **노트 보기**: 펼친 카드에서 사진 전체 보기로 넘어가는 전환.

그 뒤에 실제 데이터로 넘어간다: 사진 가져오기(EXIF 날짜), 저장(OPFS 또는 IndexedDB와 저장소 영구화), 캡션 입력(2D 화면). 실제 사진은 디코딩이 비동기라 `PhotoSource.render`를 비동기로 바꾸고, 사진이 오기 전에는 테두리와 라벨만 그린 카드를 보인다.
