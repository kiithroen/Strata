# 로드맵

## 지금 상태

Vite + TypeScript + Three.js 웹 앱 틀과 위젯 갤러리가 있다. 주 화면은 우주 보기(`cosmos`)다. 시간 묶음은 가장 최근 시점을 원점에 두고 3차원 사방으로 감겨 퍼지는 고정 로그 구면 나선 위의 빛나는 노드이고, 노드에서 노트 점이 방사형 선으로 뻗으며 한 단계 위 허브에 가지로 이어진다. 화면은 짙은 남색 바탕에 청록·파랑 빛 테마다. 노트 몇 장은 노드 둘레를 카메라를 바라본 채 천천히 도는 둥근 모서리의 양면 홀로그램 유리 카드(사진은 청록, 메모는 글 양에 맞춘 포스트잇 색, 문서는 푸른 세로 카드)이고, 멀수록 단순한 모양이 된다. 은하에서 노드나 카드를 처음 탭하면 그 노드로 다가가 빛이 커지고, 한 번 더 탭하면 그 묶음이 날짜별 수평 층(아래에서 빛기둥이 올라오고 층마다 HUD 링이 도는 홀로그램 원판)으로 쌓인 지층 보기로 바뀌고(카드는 지층에서만 펼친다), 지층에 깔린 창은 휘거나 흔들리지 않고, `카드 보기`로 그 지층의 노트만 3D 카드 공간(앞뒤로 날며 훑기)이나 2D 카드 목록(HTML)으로 본다. 원판 바깥을 탭하거나 뒤로 가면 은하로 돌아온다. 멀어지면 묶음 위에 태그 워드 클라우드가 뜨고 카드가 사라진다. 은하의 날짜 글자는 화면에 같은 크기로 보인다. 카메라는 표준 3D 궤도 시점(회전·팬·연속 줌·노드 포커스)이며, 시간 모델은 시간축 위젯이, 카드는 노트 카드 위젯이, 포인터 입력·3D 궤도·시간 띠는 카메라·제스처 위젯이 맡는다([widgets.md](widgets.md)).

- 확인한 것: 단위 테스트(주사율 무관성, 디코딩 큐·이미지 머리·킵 노트 읽기, 프레임 통계·품질 프리셋과 저장 값, 달력 눈금·묶음, 로그 구면 나선·궤도 거리, 허브·노트 점 배치, 카드 궤도, 묶음이 바뀔 때의 이동, 지층 층 쌓기·창 깔기·눕힌 자세, 태그 세기·워드 클라우드 배치·보이는 정도, 포인터 제스처 해석, 은하 탭 두 단계, 2D 카드 목록 묶기, 카드 공간 배치·앞뒤 이동, 3D 궤도 회전·팬·연속 줌·포커스 이동, 시간축 끌기·관성·핀치 시점 고정·단계 스냅)
- 로컬 탐색기(`?w=explorer`): 데스크톱 브라우저에서 폴더를 골라(폴더 고르기, 없으면 폴더 입력) 2D 격자로 하위 폴더를 오가고, 사진·동영상·음악·텍스트를 전체 화면 뷰어로 연다. 사진 썸네일은 보이는 칸만 만들고, 지금 폴더의 사진을 은하로 볼 수 있다. 확인 스크립트로 만든 샘플 폴더(사진·WebM·WAV·UTF-8과 EUC-KR 텍스트)로 1440×900과 접은 화면에서 확인했다
- 실기기 확인 도구: 오른쪽 위 설정 화면의 성능 표시(사진 디코딩 큐 포함)와 품질(프리셋·항목별), 큐브맵에 굽는 성운
- 실데이터 임시 주입: 설정 화면에서 로컬 사진(EXIF 촬영 시각·방향)과 구글 킵 테이크아웃 JSON(메모·문서·라벨 태그)을 골라 은하에 띄운다. 사진은 크기만 먼저 읽고 동시 작업 수를 제한한 큐로 비동기 디코딩해 카드에 늦게 그린다
- 실기기 성능: 폰 한 대에서 기본 품질(가짜 노트 수)로 주사율만큼 프레임이 나온다. 조작하는 동안 120Hz, 손을 떼면 60Hz인데 기기의 적응형 주사율로 보인다
- 확인하지 않은 것: 실제 폴더 고르기 창과 최근 폴더 다시 열기의 권한 흐름(스크립트로 열 수 없다), 사진 수천 장 폴더의 썸네일 속도와 격자 스크롤, 폰 실기기에서의 탭·끌기·핀치 손맛과 반응, 홀로그램 카드·지층 보기·워드 클라우드의 실기기 모습, 폴더블 접기와 펼치기, 다른 기기의 성능, 실제 폰 사진 수백 장(데스크톱에서 만든 사진 150장으로만 확인)에서의 디코딩 시간·카드 텍스처 메모리, 폰 브라우저의 폴더 고르기, EXIF 방향이 있는 실제 사진에서 `createImageBitmap` 축소 폭이 돌린 뒤 기준인지

## 다음 작업

앱은 같은 테마에 모드 둘을 둔다. **메모 앨범**(지금의 Strata: 구글 드라이브와 동기화되는 노트·사진 앨범)과 **로컬 탐색기**(기기의 폴더를 훑고 사진·동영상·음악·텍스트를 여는 탐색기. 관리 기능은 뒤로 미룬다)다. 각 단계는 갤러리 데모, 단위 테스트, 화면 캡처 확인까지 마쳐야 끝난다.

### 로컬 탐색기 모드

탐색기의 주 화면은 같은 테마의 2D(경로 막대, 폴더 목록, 썸네일 격자)이고, 뷰어·플레이어도 2D 전체 화면이다. 폴더의 사진·동영상을 시간순으로 훑을 때는 메모 앨범의 은하·지층으로 연다. 파일 접근은 `FileSource` 인터페이스 뒤에 두고 실행 환경마다 구현을 갈아 끼운다.

1. **탐색기 다듬기**: 실제 큰 폴더(사진 수천 장)로 썸네일 속도와 격자 스크롤을 보고 필요하면 칸을 보이는 만큼만 만든다(가상 스크롤). 썸네일 캐시, 동영상 썸네일, 목록 보기(이름·크기·수정 시각 열), 격자 키보드 조작(방향키로 칸 옮기기·엔터로 열기), 큰 텍스트 나눠 읽기, 탐색기에서 은하로 갔다가 돌아오면 보던 폴더로 돌아오기.
2. **앱으로 감싸기**: 안드로이드는 Capacitor 앱의 `FileSource`(모든 파일 접근 권한, 직접 설치하는 APK라 쓸 수 있다)를, 윈도우는 Capacitor용 Electron 플랫폼(Capawesome)의 Node `fs` `FileSource`와 디스크 썸네일 캐시를 붙인다. mkv 같은 브라우저가 못 여는 형식은 이때 ffmpeg 같은 네이티브 도구로 다룬다.

### 메모 앨범 모드

1. **구글 드라이브 연동**: 아래 "앱과 동기화"의 드라이브 구조를 브라우저에서 먼저 만든다. 구글 로그인(Google Identity Services 토큰, `drive.file` 범위)으로 드라이브의 `Strata/` 폴더를 읽어 은하에 띄우고, 노트를 만들거나 고치면 그 폴더에 쓴다. 브라우저 단계의 로컬 사본은 드라이브에서 다시 받을 수 있는 캐시로만 둔다. 노트 기록 형식과 합치기 규칙은 있다([sync.md](sync.md)). 남은 것은 로그인, 드라이브 읽기·쓰기, 은하에 띄우기이고, 웹 OAuth 클라이언트가 있어야 시작한다(아래 "준비").
2. **노트 입력과 보기**: 메모/태그 입력 오버레이, 카드를 눌러 사진 전체·긴 글 전체를 보는 화면, 검색을 붙이고, 은하에서 다가간 노드로도 카드 보기를 열 수 있게 한다. 메모 입력에서 포스트잇 색을 고르면 노트의 `tint`(색 번호)로 저장한다.
3. **실기기 손맛과 두 단계 탐색 다듬기**: 화면 기준은 폴드 펼친 화면(CSS 936×858, [development.md](development.md) "검증")이다. 폰에서 갤러리를 열어([development.md](development.md) "폰에서 열기", "설정 화면") 보고 `src/config.ts`에서 고친다. 웹 페이지는 주사율을 요청할 수 없으니 손을 뗐을 때의 60Hz는 앱으로 감쌀 때 안드로이드 쪽에서 요청해 본다.
   - 은하 탭 두 단계: 다가가는 거리(`cosmos.approach.planetDistance`, `hubDistance`)와 다가간 노드 표시(`cosmos.approach.glowScale`)가 손가락으로 충분히 알아볼 만한지
   - 제스처 손맛, 카드 크기·공전 속도와 탭 정확도, 선 굵기, 은하 밀도
   - 카드: 단순한 모양·흑백으로 바뀌는 시점(`card.lod`), 빛 번짐(`card.holo.glowRatio`), 메모 크기 범위(`card.memo`)
   - 지층 보기: 층 간격·내려다보는 각도·창 크기(`strata.layerGap`, `strata.pitch`, `strata.cardScale`), 창 간격(`strata.cellGap`), 링·빛기둥 밝기(`strata.ring`, `strata.beam`). 아래층으로 가려면 원판 빈 곳을 정확히 탭해야 하므로 위아래로 끌어 층을 넘기는 조작을 검토한다
   - 워드 클라우드: 멀리서 본 은하의 낱말 밀도(`cloud.maxWords`, `cloud.show`)와, 멀리서 층들이 화면에서 붙을 때 층마다 뜬 낱말이 겹치는 문제
4. **실데이터 검증**: 폰에서 실제 사진 수백 장과 드라이브 노트를 띄워 성능 표시로 디코딩이 다 끝나는 시간, 텍스처 수, 프레임을 본다. 텍스처 메모리가 문제면 카드 텍스처를 아틀라스로 묶거나 거리별로 해상도를 낮추고, 디코딩이 늦으면 카메라에 가까운 카드부터 디코딩하도록 큐 순서를 바꾼다. 폰에서 카드 공간 모드의 끌기 속도(`cardField.dollyPerPx`)와 카드 밀도를 본다.
5. **시각 확장 (성능 예산 내)**: 실기기 프레임 여유를 보고 **여러 해를 은하로** 묶는 바깥 단계와 **후처리**(블룸은 있다. 디더링 등 더할 효과는 효과별 토글로, 카드 셰이더의 홀로그램 빛·색수차와 겹치지 않게)를 반영한다. 폰에서 블룸을 켠 프레임과 끈 프레임을 성능 표시로 비교한다.

### 앱과 동기화

- **앱**: 지금 웹 코드를 Capacitor로 감싼다. 안드로이드는 APK를 직접 설치하고, 윈도우는 Capacitor용 Electron 플랫폼(Capawesome)으로 만든다. 웹 코드는 파일·저장소 접근을 인터페이스로 두어 감싸는 쪽을 바꿀 수 있게 한다. GitHub Pages 배포본은 가짜 데이터로 화면을 확인하는 미리보기로 남긴다.
- **로컬 저장**: 메타데이터(노트 번호, 시각, 캡션, 태그, 수정 시각)는 SQLite, 사진과 썸네일은 앱 파일 저장소에 둔다. 화면은 이것만 읽는다. 앱에서는 브라우저 저장소(IndexedDB·OPFS)를 지워질 수 있어 원본으로 쓰지 않는다.
- **동기화**: 구글 드라이브의 보이는 폴더(`Strata/`) 하나에 노트마다 메타데이터 JSON 하나와 사진 파일 하나를 둔다. 권한은 앱이 만든 파일만 다루는 `drive.file` 범위로 한다. 앱을 열 때와 노트를 고친 뒤 드라이브 변경 목록(Changes API)으로 받고 보낸다. 같은 노트가 양쪽에서 바뀌면 수정 시각이 늦은 쪽이 이기고, 지운 노트는 지움 표시를 남긴다.
- **사진 크기**: 드라이브에는 줄인 사본(긴 변 기준)을 올리고 원본은 폰 갤러리에 둔다. 처음 동기화가 클 수 있어 와이파이에서만 사진을 받는 설정을 둔다.
- **준비**: 구글 클라우드 프로젝트에서 Drive API를 켜고, OAuth 동의 화면을 테스트 상태로 두어 본인 계정을 테스트 사용자로 넣는다. 브라우저 단계는 웹 애플리케이션 OAuth 클라이언트(승인된 자바스크립트 원본: 개발 서버 주소와 GitHub Pages 주소)가, 안드로이드 앱은 안드로이드용 OAuth 클라이언트(패키지 이름, 서명 키 SHA-1)가 필요하다. 클라이언트 ID는 비밀이 아니어서 설정에 둔다.

### 다른 축(태그)

태그가 입력되면 날짜 대신 태그를 축으로 고를 수 있게 한다. 지금 우주 보기는 날짜에 묶여 있어서(`AxisController`의 시각·축척, 달력 단위 묶음, 시각 → 깊이) 그때 아래처럼 나눈다.

- **묶음 공급자와 관련도**: 노트 목록을 받아 노드(키, 글자, 구성원, 각 구성원의 관련도, 위 노드, 정렬값)를 내는 인터페이스를 두고, 날짜 묶음을 그 구현 하나로 옮긴다. 태그 묶음이 두 번째 구현이다. 날짜 축의 시간 중심성 대신 태그 축에서는 태그 집중도(한 노드에 몰린 노트일수록 강한 인력)가 관련도가 된다.
- **정렬값 → 깊이**: 날짜는 시각을 그대로 쓴다. 태그는 순서가 없으니 정렬값(가장 최근 노트 시각, 노트 수 등)을 정해 나선 위 깊이로 바꾼다.
- **여러 소속**: 날짜는 노트 하나가 노드 하나에 속하지만 태그는 여러 노드에 속한다. 카드는 소속 노드들 사이(가중 평균 자리) 둘레를 돌고, 소속 노드마다 선을 카드 중심에 잇는다. 선 여러 가닥이 한 카드로 모이는 모양이 된다.
- **단계(확대·축소)**: 날짜는 달력 단위로 합치고 가른다. 태그는 태그 계층(상위 태그)이나 묶음 크기로 합치고 가른다.
