# 로드맵

## 지금 상태

Vite + TypeScript + Three.js 웹 앱 틀과 위젯 갤러리가 있다. 주 화면은 우주 보기(`cosmos`)다. 시간 묶음은 가장 최근 시점을 원점에 두고 3차원 사방으로 감겨 퍼지는 고정 로그 구면 나선 위의 빛나는 노드이고, 노드에서 노트 점이 방사형 선으로 뻗으며 한 단계 위 허브에 가지로 이어진다. 화면은 짙은 남색 바탕에 청록·파랑 빛 테마다. 노트 몇 장은 노드 둘레를 카메라를 바라본 채 천천히 도는 둥근 모서리의 양면 홀로그램 유리 카드(사진은 청록, 메모는 글 양에 맞춘 포스트잇 색, 문서는 푸른 세로 카드)이고, 멀수록 단순한 모양이 된다. 은하에서 시점을 옮겼거나 노드에 다가갔을 때는 `최근으로` 단추나 `Home` 키로 최신 시점으로 돌아온다. 은하에서 노드나 카드를 처음 탭하면 그 노드로 다가가 빛이 커지고(`지층 보기`·`카드 보기` 단추가 뜬다), 한 번 더 탭하거나 `지층 보기` 단추를 누르면 그 묶음이 날짜별 수평 층(아래에서 빛기둥이 올라오고 층마다 HUD 링이 도는 홀로그램 원판)으로 쌓인 지층 보기로 바뀌고(카드는 지층에서만 펼친다), 지층에 깔린 창은 휘거나 흔들리지 않으며 층마다 칸 수가 정해져 있어(바라보는 층이 더 많다) 노트가 넘치면 칸이 거품처럼 꺼지고 다른 노트로 부풀며 돌아가고, `▲`·`▼` 단추·방향키·층 기간으로 좁혀진 시간 띠로 층을 옮기며 `카드 보기`로 그 지층의 노트만 3D 카드 공간(앞뒤로 날며 훑기, 관성 이동·깊이 진행 막대 포함)이나 2D 카드 목록(HTML)으로 본다. 원판 바깥을 탭하거나 뒤로 가면 은하로 돌아온다. 은하에서 다가간 노드로도 `카드 보기`를 연다. 메모 앨범은 은하와 지층 보기의 `+ 노트`로 메모·체크리스트·사진 노트를 써서 브라우저 IndexedDB에 저장하고(저장된 노트가 없으면 가짜 노트를 `미리보기` 배지와 함께 띄우며, 고친 내용이 있을 때 `취소`·`Esc`·뒤로는 `변경 버리기`로 한 번 더 확인하고, 기존 자주 쓰는 태그 추천 칩을 제공한다), 펼친 카드를 다시 탭하거나 카드 목록의 카드를 누르면 사진 전체·글 전체를 읽는 노트 보기가 열려 저장된 노트를 고치고 지우며(`삭제 확인` 두 단계와 자동·바깥 탭 해제), 사진 확대·팬과 축 잠금 터치 스와이프를 지원한다. 체크리스트 항목은 보기 화면에서 바로 체크하고 닫으면 씬을 다시 띄우지 않고 카드·목록에 즉시 부분 반영한다. 은하와 지층 보기의 `검색`과 카드 목록·노트 보기의 `#태그` 클릭은 제목·본문·태그로 찾아 2D 목록으로 펼친다. 묶음마다 태그 워드 클라우드가 늘 떠 있고, 멀어지면 카드가 사라진다. 은하의 날짜 글자는 화면에 같은 크기로 보이고, 하단 안내 줄은 지금 조작 상태에 맞춰 바뀐다. 카메라는 표준 3D 궤도 시점(회전·팬·연속 줌·노드 포커스)이며, 시간 모델은 시간축 위젯이, 카드는 노트 카드 위젯이, 포인터 입력·3D 궤도·시간 띠는 카메라·제스처 위젯이 맡는다([widgets.md](widgets.md)).

- 확인한 것: 단위 테스트(주사율 무관성, 디코딩 큐·이미지 머리·킵 노트 읽기, 프레임 통계·품질 프리셋과 저장 값, 달력 눈금·묶음, 로그 구면 나선·궤도 거리, 허브·노트 점 배치, 카드 궤도, 묶음이 바뀔 때의 이동, 지층 층 쌓기·칸 잡기·눕힌 자세, 칸 돌려 쓰기(`TileRotation`), 태그 세기·워드 클라우드 배치·먼 카드 숨김, 포인터 제스처 해석, 은하 탭 두 단계, 2D 카드 목록 묶기, 카드 공간 배치·앞뒤 이동·관성 이동, 3D 궤도 회전·팬·연속 줌·포커스 이동, 시간축 끌기·관성·핀치 시점 고정·단계 스냅, 노트 입력 모델·태그 나누기·태그 토글·입력 변경 비교(`sameDraft`)·검색, 앨범 저장·고치기·지움 표시·체크, 체크리스트 줄 변환과 기록 검사, 공용 사진 줌·팬 모델(`imageZoom`), 노트 보기의 넘길 차례·축 잠금 가로 끌기 판정(`lockSwipeAxis`·`swipeStep`), 탐색기 격자 배치·보이는 줄·키보드 커서 이동·숨긴 파일 표시(`visibleEntries`)·상위 경로 자식 찾기(`childOnPath`)·정렬 방향(`SortDir`)·이름 필터(`filterEntries`), 썸네일 LRU 캐시, 텍스트 이어 읽기의 조각 경계·인코딩 바꾸기·수동 인코딩과 파일 내 찾기(`textViewerModel`))
- 노트 입력·보기·검색·지층 UX: 데스크톱 브라우저(936×858·514×1076)에서 우주 보기 초기 `미리보기` 배지(노트 저장 시 해제)와 `최근으로` 단추·`Home` 키 시점 복귀, 카드 공간 깊이 진행 막대와 드래그 끝 관성 이동, 은하 노드 접근 시 `지층 보기`·`카드 보기` 단추와 동적 하단 안내, 지층 `▲`·`▼`·방향키·좁혀진 시간 띠와 드래그 툴팁, 설정 패널 `Esc`·바깥 탭 단독 닫기, 카드 목록과 노트 보기 `#태그` 클릭 검색(카드 목록 위 겹침과 `← 카드로` 복귀), 노트 입력의 기존 태그 추천 칩·`변경 버리기` 유실 방지·`삭제 확인` 해제를 확인했다. 메모와 사진 노트를 저장·편집·삭제하고, 다시 불러와도 남는 것, 사진 노트 보기의 휠·더블탭 줌·팬·초기화와 기본 배율 터치 스와이프 축 잠금, 카드 목록·지층 펼친 카드·검색 결과에서 노트 보기가 열리고 그 묶음 안에서 이전·다음 노트로 넘기며(단추·방향키·가로 끌기), 뒤로·`Esc`가 맨 위 화면만 닫는 것, 체크리스트를 쓰고(본문 줄 변환, 엔터로 항목 더하기) 보기 화면에서 체크한 뒤 `닫기`·`Esc`·뒤로로 닫으면 씬 전체 재로드 없이 3D 카드·2D 목록에 즉시 부분 반영되고 보던 화면으로 돌아오는 것, 저장·삭제 뒤 쌓인 방문 기록이 모두 되돌려지고 지층·카드 공간·목록·검색(지층 위에서 연 검색 포함)에서 고치거나 지운 뒤 보던 화면으로 돌아오는 것을 폴드 펼친 화면과 접은 화면 크기에서 확인했다
- 로컬 탐색기(`?w=explorer`): 데스크톱 브라우저에서 폴더를 골라(폴더 고르기, 없으면 폴더 입력) 2D 격자나 목록(이름·크기·수정 시각, `↑`/`↓` 정렬 방향 토글과 이름 필터 `/`, 상태 줄 숨긴 파일 보기 토글)으로 하위 폴더를 오가고(`↑ 위로`·뒤로 복귀 시 이전 스크롤 위치 복원), 사진·동영상·음악·텍스트를 전체 화면 뷰어로 연다. 격자·목록은 화면 근처 줄의 칸만 만드는 가상 스크롤이고, 사진·동영상 썸네일은 그 칸만 만들어 페이지가 열려 있는 동안 캐시에 둔다. 방향키·엔터로 칸을 다루고, 미디어 뷰어는 사진 줌·팬·축 잠금 스와이프, 사진·동영상 단순 탭 오버레이 UI 숨김·복귀 토글, 텍스트 줄바꿈 토글·수동 인코딩(자동·UTF-8·EUC-KR·UTF-16LE)·`Ctrl+F` 파일 내 찾기(매치 수·이전/다음 이동)와 나눠 읽기를 지원한다. 지금 폴더와 하위 폴더의 파일을 폴더 축 은하(폴더가 노드, 부모 폴더가 허브, 날짜 축으로 바꿀 수 있다)로 열고 돌아오면 보던 폴더로 온다. 확인 스크립트로 만든 샘플 폴더(사진 3000장·WebM·WAV·UTF-8과 EUC-KR 텍스트·8MB 텍스트·미지원 `.zip`/`.exe` 파일·긴 하위 폴더 목록)로 1440×900과 514×1076 접은 화면에서 확인했고, 숨긴 파일 토글과 미지원 파일 안내, 하위 폴더 복귀 시 `scrollTop` 복원, 사진 줌·팬·단순 탭 오버레이 토글·스와이프, 텍스트 줄바꿈·인코딩 전환·파일 내 찾기, 이름 필터·정렬 방향 전환·514×1076 레이아웃도 같은 크기에서 확인했다. 데스크톱 OPFS의 3000개 폴더는 목록 0.2초, 은하로 보기 600장 읽기 0.5초였다
- AI 요약과 태그: 긴 메모·문서를 Gemini API로 요약하고 태그를 붙여 노트 기록에 적고(드라이브 형식의 `summary`), 카드는 멀면 단순한 모양, 중간 거리는 요약, 가까우면 본문을 보인다. AI 태그는 검색·목록·워드 클라우드에 쓰이고 노트 보기에 흐리게 보인다. 글이 바뀔 때만, 고친 뒤 잠시 기다렸다 다시 만든다. 요약 차례·기록·태그 규칙은 단위 테스트로, 카드 세 단계와 설정 화면은 화면 캡처로, 개발 서버 프록시(`GEMINI_API_KEY`)로 저장한 메모가 기다린 뒤 요약·태그를 받아 검색과 노트 보기에 반영되는 것은 데스크톱 브라우저에서 확인했다
- 실기기 확인 도구: 오른쪽 위 설정 화면의 성능 표시(사진 디코딩 큐 포함)와 품질(프리셋·항목별), 큐브맵에 굽는 성운
- 실데이터 임시 주입: 설정 화면에서 로컬 사진(EXIF 촬영 시각·방향)과 구글 킵 테이크아웃 JSON(메모·문서·라벨 태그)을 골라 은하에 띄운다. 사진은 크기만 먼저 읽고 동시 작업 수를 제한한 큐로 비동기 디코딩해 카드에 늦게 그린다
- 실기기 성능: 폰 한 대에서 기본 품질(가짜 노트 수)로 주사율만큼 프레임이 나온다. 조작하는 동안 120Hz, 손을 떼면 60Hz인데 기기의 적응형 주사율로 보인다
- 확인하지 않은 것: 설정 화면에 넣은 키로 브라우저에서 Gemini API를 바로 부르는 경로(배포본), 노트 수백 장의 요약 비용과 태그 품질, 실제 폴더 고르기 창과 최근 폴더 다시 열기의 권한 흐름(스크립트로 열 수 없다), 보이는 창에서의 썸네일 굽는 속도와 스크롤 손맛, 폰 실기기에서의 탭·끌기·핀치 손맛과 반응, 홀로그램 카드·지층 보기·워드 클라우드의 실기기 모습, 폴더블 접기와 펼치기, 다른 기기의 성능, 실제 폰 사진 수백 장(데스크톱에서 만든 사진 150장으로만 확인)에서의 디코딩 시간·카드 텍스처 메모리, 폰 브라우저의 폴더 고르기, EXIF 방향이 있는 실제 사진에서 `createImageBitmap` 축소 폭이 돌린 뒤 기준인지, 폰에서의 노트 입력(가상 키보드가 입력 칸을 가리는지, 사진 고르기 창, 실제 폰 사진의 사본 굽기 시간과 EXIF 방향), 브라우저가 저장소 영구화를 거절했을 때 노트가 지워지는지

## 다음 작업

앱은 같은 테마에 모드 둘을 둔다. **메모 앨범**(지금의 Strata: 구글 드라이브와 동기화되는 노트·사진 앨범)과 **로컬 탐색기**(기기의 폴더를 훑고 사진·동영상·음악·텍스트를 여는 탐색기. 관리 기능은 뒤로 미룬다)다. 각 단계는 갤러리 데모, 단위 테스트, 화면 캡처 확인까지 마쳐야 끝난다.

### 공통 손질

1. **맨 위 화면 판정**: 설정 패널이 다른 화면의 `body` 클래스 목록으로 자신이 맨 위인지 판정한다. 오버레이가 늘면 깨지므로 공용 오버레이 스택으로 바꾼다. 입력 중인 요소 판정(`INPUT`·`TEXTAREA`·`SELECT`·`isContentEditable`)도 네 곳에 흩어져 있어 도우미 하나로 묶는다(`MediaViewer`는 `isContentEditable`이 빠져 있다).
2. **큰 목록·파일 성능**: 텍스트 뷰어 찾기가 조각을 읽을 때마다 전체를 다시 검색하고 강조를 통째로 다시 그린다(새 조각만 검색하고 입력은 디바운스한다). 탐색기 이름 필터가 글자마다 `reset()`으로 썸네일 작업을 버린다(칸을 재사용하거나 디바운스한다). 찾기는 소문자로 바꾼 문자열의 위치를 원문에 그대로 써서 길이가 바뀌는 글자(`İ`) 뒤에서 강조가 밀린다.
3. **`최근으로` 단추 조건**: 은하에서 확대·회전만 바꾼 경우에도 되돌릴 시점이 있는데 단추가 숨어 있다(목표점 이동만 본다).
4. **은하 밀도**: 지층 칸 상한·돌려 쓰기와 은하 살 상한(`graph.maxSpokes`)은 있다. 폴더 축 은하는 파일 시각이 비슷한 폴더들이 나선 위 거의 같은 자리에 붙고 노드마다 카드가 돌아, 파일 수백 개 폴더 몇 개만으로도 카드가 한 덩어리로 겹친다. 폴더 축의 나선 자리를 시각 대신 폴더 차례로 벌리거나, 겹친 노드끼리 밀어내거나, 다가가지 않은 노드의 카드 수를 줄이는 방법을 본다. 실제 킵 데이터를 넣어 날짜 축에서도 같은지 본다. 지층 칸 수(`strata.maxTiles`, `sideTiles`)와 머무는 시간(`strata.rotate`)은 실기기에서 맞춘다.

### 로컬 탐색기 모드

탐색기의 주 화면은 같은 테마의 2D(경로 막대, 폴더 목록, 썸네일 격자)이고, 뷰어·플레이어도 2D 전체 화면이다. 폴더의 사진·동영상을 시간순으로 훑을 때는 메모 앨범의 은하·지층으로 연다. 파일 접근은 `FileSource` 인터페이스 뒤에 두고 실행 환경마다 구현을 갈아 끼운다.

1. **탐색기 실폴더 확인**: 실제 폴더 고르기로 사진 수천 장 폴더를 열어 보이는 창에서 썸네일 속도와 빠르게 끌 때의 빈 칸을 보고 `explorer.decodeConcurrency`·`explorer.preloadPx`·`explorer.thumbCacheMB`를 정한다. 지금 디코딩 큐는 들어온 순서라, 빠르게 끈 뒤 화면 칸이 늦게 차면 화면 안 칸을 앞에 끼운다. 은하로 보기는 데스크톱에서 빨라 늦게 채우기를 두지 않았다. 폰(앱 `FileSource`)에서 느리면 은하를 먼저 띄우고 카드를 늦게 채운다.
2. **앱으로 감싸기**: 안드로이드는 Capacitor 앱의 `FileSource`(모든 파일 접근 권한, 직접 설치하는 APK라 쓸 수 있다)를, 윈도우는 Capacitor용 Electron 플랫폼(Capawesome)의 Node `fs` `FileSource`와 디스크 썸네일 캐시를 붙인다. mkv 같은 브라우저가 못 여는 형식은 이때 ffmpeg 같은 네이티브 도구로 다룬다.

### 메모 앨범 모드

1. **AI 요약·태그 다듬기**: 실제 노트 여럿으로 요약 길이(`album.summary.maxChars`)·글자 크기(`card.summary`)가 카드에 맞는지, 요약 ↔ 본문이 바뀌는 거리(`card.lod.body`)가 자연스러운지, AI 태그가 흩어지지 않고 묶음에 도움이 되는지 본다. 배포본에서 설정의 키로 부르는 경로를 확인하고, 앱으로 감쌀 때 키를 기기 보안 저장소로 옮긴다.
2. **노트 입력 폰 확인**: 폰에서 입력 화면(가상 키보드가 입력 칸·항목 줄을 가리는지, 사진 고르기 창, 체크리스트 항목 줄의 엔터·지우기 키)과 카드의 체크 표시 글자(☐ ☑)가 폰 글꼴에 있는지 본다.
3. **실기기 손맛과 두 단계 탐색 다듬기**: 화면 기준은 폴드 펼친 화면(CSS 936×858, [development.md](development.md) "검증")이다. 폰에서 갤러리를 열어([development.md](development.md) "폰에서 열기", "설정 화면") 보고 `src/config.ts`에서 고친다. 웹 페이지는 주사율을 요청할 수 없으니 손을 뗐을 때의 60Hz는 앱으로 감쌀 때 안드로이드 쪽에서 요청해 본다.
   - 은하 탭 두 단계: 다가가는 거리(`cosmos.approach.planetDistance`, `hubDistance`)와 다가간 노드 표시(`cosmos.approach.glowScale`)가 손가락으로 충분히 알아볼 만한지
   - 제스처 손맛, 카드 크기·공전 속도와 탭 정확도, 선 굵기, 은하 밀도
   - 카드: 단순한 모양·흑백으로 바뀌는 시점(`card.lod`), 빛 번짐(`card.holo.glowRatio`), 메모 크기 범위(`card.memo`)
   - 지층 보기: 층 간격·내려다보는 각도·창 크기(`strata.layerGap`, `strata.pitch`, `strata.cardScale`), 창 간격(`strata.cellGap`), 링·빛기둥 밝기(`strata.ring`, `strata.beam`). `▲`·`▼` 단추·방향키·시간 띠 외에 위아래로 끌어 층을 넘기는 조작도 실기기 손맛을 보며 검토한다
   - 워드 클라우드: 늘 떠 있는 낱말의 밀도(`cloud.maxWords`)와, 가까이서 노드 둘레 카드와 낱말이 겹쳐 읽기 어려운지, 멀리서 층들이 화면에서 붙을 때 층마다 뜬 낱말이 겹치는 문제
4. **실데이터 검증**: 폰에서 실제 사진 수백 장과 노트를 띄워 성능 표시로 디코딩이 다 끝나는 시간, 텍스처 수, 프레임을 본다. 텍스처 메모리가 문제면 카드 텍스처를 아틀라스로 묶거나 거리별로 해상도를 낮추고, 디코딩이 늦으면 카메라에 가까운 카드부터 디코딩하도록 큐 순서를 바꾼다. 폰에서 카드 공간 모드의 끌기 속도(`cardField.dollyPerPx`)와 카드 밀도를 본다.
5. **시각 확장 (성능 예산 내)**: 실기기 프레임 여유를 보고 **여러 해를 은하로** 묶는 바깥 단계와 **후처리**(블룸은 있다. 디더링 등 더할 효과는 효과별 토글로, 카드 셰이더의 홀로그램 빛·색수차와 겹치지 않게)를 반영한다. 폰에서 블룸을 켠 프레임과 끈 프레임을 성능 표시로 비교한다.
6. **구글 드라이브 연동**: 탐색기와 메모 앨범의 로컬 작업을 다 마친 뒤에 붙인다. 아래 "앱과 동기화"의 드라이브 구조를 브라우저에서 먼저 만든다. 구글 로그인(Google Identity Services 토큰, `drive.file` 범위)으로 드라이브의 `Strata/` 폴더를 읽어 은하에 띄우고, 노트를 만들거나 고치면 그 폴더에 쓴다. 브라우저 단계의 로컬 사본은 드라이브에서 다시 받을 수 있는 캐시로만 둔다. 노트 기록 형식과 합치기 규칙은 있다([sync.md](sync.md)). 남은 것은 로그인, 드라이브 읽기·쓰기, 은하에 띄우기이고, 웹 OAuth 클라이언트가 있어야 시작한다(아래 "준비").

### 앱과 동기화

- **앱**: 지금 웹 코드를 Capacitor로 감싼다. 안드로이드는 APK를 직접 설치하고, 윈도우는 Capacitor용 Electron 플랫폼(Capawesome)으로 만든다. 웹 코드는 파일·저장소 접근을 인터페이스로 두어 감싸는 쪽을 바꿀 수 있게 한다. GitHub Pages 배포본은 가짜 데이터로 화면을 확인하는 미리보기로 남긴다.
- **로컬 저장**: 메타데이터(노트 번호, 시각, 캡션, 태그, 수정 시각)는 SQLite, 사진과 썸네일은 앱 파일 저장소에 둔다. 화면은 이것만 읽는다. 앱에서는 브라우저 저장소(IndexedDB·OPFS)를 지워질 수 있어 원본으로 쓰지 않는다.
- **동기화**: 구글 드라이브의 보이는 폴더(`Strata/`) 하나에 노트마다 메타데이터 JSON 하나와 사진 파일 하나를 둔다. 권한은 앱이 만든 파일만 다루는 `drive.file` 범위로 한다. 앱을 열 때와 노트를 고친 뒤 드라이브 변경 목록(Changes API)으로 받고 보낸다. 같은 노트가 양쪽에서 바뀌면 수정 시각이 늦은 쪽이 이기고, 지운 노트는 지움 표시를 남긴다.
- **사진 크기**: 드라이브에는 줄인 사본(긴 변 기준)을 올리고 원본은 폰 갤러리에 둔다. 처음 동기화가 클 수 있어 와이파이에서만 사진을 받는 설정을 둔다.
- **준비**: 구글 클라우드 프로젝트에서 Drive API를 켜고, OAuth 동의 화면을 테스트 상태로 두어 본인 계정을 테스트 사용자로 넣는다. 브라우저 단계는 웹 애플리케이션 OAuth 클라이언트(승인된 자바스크립트 원본: 개발 서버 주소와 GitHub Pages 주소)가, 안드로이드 앱은 안드로이드용 OAuth 클라이언트(패키지 이름, 서명 키 SHA-1)가 필요하다. 클라이언트 ID는 비밀이 아니어서 설정에 둔다.

### 다른 축(태그)

태그가 입력되면 날짜 대신 태그를 축으로 고를 수 있게 한다. 노트를 노드로 묶는 방법은 `Grouping`(날짜 축, 폴더 축)으로 갈아 끼운다([widgets.md](widgets.md) "묶는 축"). 태그 축은 세 번째 구현이고, 지금 구조에 없는 것은 아래다.

- **관련도**: 날짜 축의 시간 중심성 대신 태그 집중도(한 노드에 몰린 노트일수록 강한 인력)가 관련도가 된다.
- **정렬값 → 깊이**: 날짜·폴더 축은 묶음에서 가장 최근 노트의 시각을 나선 위 깊이로 쓴다. 태그 축도 같은 정렬값으로 시작하고, 노트 수 같은 다른 정렬값이 나은지 본다.
- **여러 소속**: 날짜는 노트 하나가 노드 하나에 속하지만 태그는 여러 노드에 속한다. 카드는 소속 노드들 사이(가중 평균 자리) 둘레를 돌고, 소속 노드마다 선을 카드 중심에 잇는다. 선 여러 가닥이 한 카드로 모이는 모양이 된다.
- **단계(확대·축소)**: 날짜는 달력 단위로 합치고 가른다. 태그는 태그 계층(상위 태그)이나 묶음 크기로 합치고 가른다.
